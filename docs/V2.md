# Handpicked: v2 Spec

## Goal

Close the loop that v1 opened. An approved pick that becomes available shows up on the intended member's Plex home screen, and Handpicked records whether they watched it, abandoned it, or ignored it. The digest reports how picks are landing, per member.

v2 covers Deliver and Measure from `docs/PRODUCT.md`. It should answer whether picks are any good, with data, before scoring is tuned from that data.

## Scope

**In:**

- Track approved picks until they are available, from Seerr
- Deliver each available pick to its member in Plex, as a row on their Home screen (see open question 1)
- Take a delivered pick off the member's home screen once its outcome is settled
- Record each pick's outcome from Tautulli history: watched, abandoned, or ignored
- Report delivery, outcomes, and hit rate per member in the digest
- Record approved requests that Seerr later declines on its own (#17)

**Out (deliberately):**

- Changing scoring from outcomes. Outcomes already feed back the way any viewing does: a watched pick becomes a seed, and an abandoned one a mild negative. Anything more waits for real data.
- Telling members about a pick outside Plex, such as email. Managed users have no email.
- Hiding one member's collection from the others' Collections tab. Only the Home row is private (see open question 1).
- A web UI, LLM features, and group recommendations, as in v1

## Lifecycle

v1's lifecycle already has the states v2 fills in:

```
proposed -> requested -> approved -> available -> watched | abandoned | ignored
                      -> declined | deleted (final)
```

- **available:** Seerr reports the title available. The run that sees it delivers the pick and records `available_at` and `delivered_at`.
- **watched:** the member finished it after it became available. Same thresholds as seeds: a movie at the completion percentage, a show with at least the minimum finished episodes.
- **abandoned:** the member started it, didn't finish it, and hasn't returned for the abandon window.
- **ignored:** the member hasn't started it within the ignore window after delivery.
- **declined** after approval: Seerr declined the request on its own, such as when the title leaves Radarr or Sonarr (#17). The row keeps `approved_at`. A request that disappears after approval leaves the pick approved, since its title can still arrive.
- An ignored pick that the member starts later moves to watched or abandoned. The other outcomes are final.
- Watching before the title was available doesn't count. In practice it can't happen, since the title wasn't in the library.

Per v1's note, this is new columns and states on `suggestions` rows, not new tables. Likely: `available_at`, `delivered_at`, `undelivered_at`, `watched_at`, `abandoned_at`, `ignored_at`.

Picks approved before v2 is installed are tracked the same way from the first v2 run, so existing approved picks get delivered once available.

## Pipeline additions (each run, before picking)

1. **Sync approved picks:** for each `approved` pick, check its Seerr media status. Available moves it to `available`. A request Seerr has declined since approval (#17) moves it to `declined`.
2. **Deliver:** put each newly available pick on its member's home screen.
3. **Outcomes:** for each delivered pick without a final outcome, check the member's `watch_events` since `available_at`, and record watched, abandoned, or ignored.
4. **Undeliver:** take a pick off the home screen once it's watched, abandoned, or ignored, so the row only holds picks still waiting.

Dry runs compute and report all of this, and write nothing to Seerr or Plex.

## Outputs

- **Plex:** a "Picked for you" row of each member's waiting picks on their Home screen, and on no one else's. One row for movies and one for shows, since a collection lives in one library.
- **Digest additions, per member:**
  - delivered this run
  - outcomes since the last run, with the seeds that led to each pick ("finished X, picked because you finished Y")
  - totals and hit rate: watched / (watched + abandoned + ignored)

## Configuration

- Plex server URL and admin token, as optional template fields. Without them, Handpicked skips delivery and still measures outcomes from availability.
- Setup for the admin, in Plex: a member with an age preset (Little kid, Older kid, Teen) or an "allow only these ratings" list gets no row until the admin switches them to None with "exclude these ratings" instead. The digest names any member skipped this way, and why.
- Thresholds: ignore window (weeks after delivery), and the abandon window for picks. v1's seed thresholds may be reused where they fit.

## Open questions (verify before writing much code)

1. **Delivery route (chosen: a collection row per member, hidden from the others by label).** Researched against `python-plexapi` 4.18.3, Plex's forums, and Shortlist (an open-source tool that does this), plus read-only checks of the household's server (Plex Media Server 1.43.5, Plex Pass, all members in Plex Home).
   - **How it works:**
     - Each member gets a "Picked for you" collection in each movie and TV library, with a label of their own (for example `handpicked-<plex id>`).
     - Every other member's share filter gets `label!=` that label.
     - The collection is then promoted to "Friends' Home". Plex's only Home switches are the owner's own Home (`promotedToOwnHome`) and every shared user's Home (`promotedToSharedHome`), so the label is what keeps a row off everyone else's Home.
     - The admin's own collection is promoted to their own Home only, and needs no label. Plex never applies share filters to the server owner, so the admin's Collections tab shows every member's collection. Other members can see each other's collections there too: only the Home row is private, which is acceptable.
     - Label hiding on the Home, Recommended and Related shelves needs Plex Media Server 1.43.2.10687 or newer, and Plex Pass on the admin account. Check both at startup, and skip delivery with a clear message if either is missing.
   - **Share filters are the risky part:**
     - Plex stores each member's filter as one string per library type (`filterMovies`, `filterTelevision`), and accepts the whole string on every write.
     - In it, `&` means AND and `|` means OR, and `&` doesn't bind tighter than `|` (Shortlist measured this on a real server). So `contentRating!=R|label!=x` would switch the rating limit off.
     - `python-plexapi`'s `updateFriend` joins conditions with `|`, so Handpicked must build the string itself, joining with `&`.
     - To keep that small and safe, Handpicked only writes a filter made of exclude conditions (`contentRating!=`, `label!=`) joined by `&`. It keeps every condition it didn't write exactly as it was, and changes only its own `label!=handpicked-*` values. Any other filter (an allow list, a `|`, another field) means that member is skipped and named in the digest.
     - Plex refuses label filters (HTTP 422) on a managed user with an age preset, and an allow list would hide the member's own collection, which has no rating. Both are handled by the admin setup step under Configuration, not by Handpicked.
   - **Verified with test writes on the household server** (a one-title collection with one member's label, on 1.43.5):
     - A collection promoted to "Friends' Home" shows on a managed user's Home, and not on the admin's.
     - `label!=` hides it from another member's Home and Collections tab.
     - A member switched from a preset to "exclude these ratings" keeps those limits, and sees their own row. The collection has no rating, so rating excludes don't hide it.
     - A member's view can be read as them: `GET https://plex.tv/api/servers/<machine id>/shared_servers` gives a server token per shared member, Home and managed users included. Keep these tokens in memory only.
     - Plex saved the label with a capital first letter (`Handpicked-test-...`). Plex matches labels case-insensitively, so Handpicked compares labels decoded and case-folded, and doesn't add a rule that's already there in another case.
     - The server can be slow to build Home rows after it has been idle. A read with httpx's default 5 second timeout failed, so the Plex client needs a longer one.
   - **A full account's rules apply late.** A managed member's new `label!=` rule took effect at once. An adult member with a full Plex account still saw the row 40 minutes after the write, and no longer saw it 10 hours later, by which time their library sharing had also been edited in Plex. Sharing all libraries vs individual ones made no difference. So Handpicked must not trust a filter write:
     - Write the label rules when a member's collection is first made, unpromoted. Labels are per member, so this happens once per member, not once per pick.
     - Before promoting, read every other member's Home and Collections tab as them. Promote only once none of them sees the collection, and otherwise check again next run.
     - A new member's row can be a run late. Until it's promoted, other members can only see it in their Collections tab, which is accepted above.
   - **Ruled out:**
     - **The member's Watchlist.** Plex keeps Discover, which the Watchlist belongs to, off for managed users. It would also mix picks into an admin's own Watchlist, and Seerr can be set to request everything on a Watchlist automatically, which would skip approval.
     - **Plex Lists** (March 2026). Plex says "Managed Users have no capabilities when it comes to Lists", Lists don't show on the Home screen, and Plex has published no API for them.
     - **Playlists.** They're per user, but don't show on the Home screen.
2. **Finding the Plex item (chosen: by `tmdb://` guid).** Checked read-only against the household's Seerr and Plex.
   - Seerr's `ratingKey` can't be relied on. It was missing for 163 of 219 available movies and 58 of 99 available shows. Every one that was set pointed at the right title.
   - Plex's `guid=` filter doesn't match `tmdb://` ids. Instead, each run lists each movie and TV library once with `includeGuids=1` and maps `tmdb://` ids to items. That took under half a second per library, and found 337 of 339 owned titles.
   - The two misses were matching errors: a movie Plex had matched to the wrong item, and one where Seerr and Plex had different TMDB entries. A pick that isn't found stays undelivered, the digest names it, and the next run tries again.
3. **Availability (chosen: season 1 for TV).** A movie is available at Seerr status `available`. A show is available at `available`, or at `partially available` once season 1 is fully available. Seerr's `/media` list, filtered to `allavailable`, gives each show's season statuses, the same as `GET /tv/<tmdb id>` gave for all 21 partially available shows. So one paged list covers every pick.
   - Of the household's 21 partially available shows, 15 had season 1 complete. In most of those, only the latest season wasn't complete, some because it's still airing. None of that stops a member from starting the show.
   - A show with no season 1 in the library waits until Seerr calls it available. That's rare for picks, which request every season.
   - Seerr's sync is at most a day stale, which is fine for a weekly job.
4. **Outcome windows.** Default ignore and abandon windows, for movies and TV. A show takes longer to start and finish than a movie. Check them against the household's real history once there is some.
5. **An empty row.** Undelivering removes a title from the member's collection. Check what Plex does with a promoted collection once it's empty: hide the row, or show it empty. If it shows empty, demote the collection while it has nothing in it.
6. **What makes the server reload a full account's filter.** Time, an edit to the member's sharing in Plex, or a server restart (see open question 1). Knowing would let Handpicked bring the delay down, rather than just wait it out.
